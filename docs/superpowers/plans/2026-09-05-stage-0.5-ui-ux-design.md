# Stage 0.5 UI / UX Design & Design System Plan

Date: 2026-09-05
Status: Draft for review

## Boundary

Stage 0.5 freezes information architecture, Design System V1, interaction rules, accessibility, state matrix, page specifications, and a reviewable prototype. It does not implement Stage 1–5 business logic, Electron production UI, fake Agent progress, fake approvals, or a `07 开发区`.

## Work sequence

1. Confirm Stage 0 contracts and record the outstanding Windows VM waiver.
2. Produce the Design System V1 tokens, typography, spacing, density, motion, and component states.
3. Define App Shell and six product modules plus Agent Center, Settings, Model Center, Permission Center, Workspace, Connectors, and Diagnostics.
4. Write page specifications for Dashboard, Agent Center, Course, English, Project, Knowledge, News, and Settings.
5. Define loading, empty, error, offline, read-only, approval, running, paused, failed, cancelled, and completed states.
6. Define accessibility and keyboard behavior for Windows desktop.
7. Build a high-fidelity prototype using only documented contracts and fixture states.
8. Run design review, visual review, and security/permission review.
9. Record approval or requested changes; only an approved Design System V1 unlocks Stage 1 implementation planning.

## Review gates

- No page invents a domain object outside Domain Core.
- Every mutation names its command, permission scope, approval state, and failure state.
- Renderer remains presentation-only and uses typed Preload APIs.
- Future modules may be designed but their business actions remain unavailable until their stage.
- No design path can modify UniForge source, installation, updater, migrations, permission kernel, or build/signing infrastructure.

## Acceptance

Stage 0.5 is ready for approval when all design documents are complete, prototype flows cover the core states, accessibility review is recorded, and the user approves Design System V1 and core prototypes. This plan does not close Stage 0.
